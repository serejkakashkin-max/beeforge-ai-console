# OpenCode: агенты и MCP

После изменения `opencode.json` перезапустите OpenCode или создайте новую сессию.

## Изображения (vision-модели)

Если для выбранной GGUF-модели доступен совместимый `mmproj*.gguf`, менеджер показывает его на вкладке «Основные». Включите «Vision для этой модели», проверьте добавку памяти на вкладке «Ресурсы», сохраните профиль и запустите/перезапустите сервер. Только тогда синхронизация выставит для модели OpenCode поддержку вложений и изображений.

`mmproj` должен соответствовать семейству и версии основной GGUF; менеджер предпочитает файл из той же папки модели. Не включайте vision для текстовой модели или для projector от другой модели. По умолчанию projector остаётся в RAM — это безопаснее для Q2/162K, который почти заполняет 16 GB VRAM. Опцию «Projector на GPU» включайте только если вкладка «Ресурсы» показывает достаточный VRAM headroom.

## Как выбирать режим

| Что нужно сделать | Команда / агент | Что используется |
|---|---|---|
| Любая командная задача | выберите `team-lead` и опишите задачу обычными словами | FAST по умолчанию; последовательное делегирование подходящим агентам через `task` |
| Разработка и рефакторинг | `software-engineer` | Serena, LSP, диагностика ошибок и актуальная документация Context7 |
| QA, регрессия, E2E и browser diagnostics | `/review`, `/web`, `/debug-browser` или `qa-engineer` | Quality Engineer: Playwright для E2E, Chrome DevTools для диагностики |
| Работа с Windows, процессами, файлами и SSH | `/operate <задача>`, `/ssh <задача>` или `systems-engineer` | Windows UI MCP, shell, OpenSSH |
| Репозитории, Issues, PR, Actions и релизы | `/github <задача>` или `devops-engineer` | официальный GitHub MCP с записью |
| Контейнеры, Compose, логи и образы | `/docker <задача>` или `platform-engineer` | Docker MCP в режиме без разрушительных операций |
| Архитектура, сравнение вариантов, план | `/research <задача>` или `solution-architect` | Docker MCP Toolkit + Sequential Thinking |
| AppSec и secure-design review | `/security <задача>` или `security-engineer` | read-only анализ, SCA и MCP/agent audit; активные проверки только после явного подтверждения |

## Примеры

```text
/lead подготовь выпуск: проверь Docker Compose, протестируй локальный сайт, найди незакрытые ошибки GitHub Actions и составь единый отчёт. Ничего внешнего не меняй без согласования.
```

`team-lead` — единая точка входа и координатор, а не ещё один набор опасных инструментов. Выбирайте его для обычной работы и задавайте режим естественным текстом: без уточнения действует FAST, «проверь стандартно/включая мобильную версию» включает STANDARD, а «релизная проверка/максимально тщательно» — RELEASE. При `parallel=1` специалисты запускаются последовательно.

```text
/web открой http://localhost:3000, пройди главный сценарий и сообщи console errors
```

```text
/debug-browser проверь, почему после отправки формы растёт время ответа API
```

```text
/github в репозитории owner/repo найди открытые ошибки CI и подготовь PR с исправлением
```

```text
/docker покажи все контейнеры, состояние Compose и последние 100 строк логов api
```

```text
/research сравни два варианта архитектуры кэширования и предложи план внедрения с рисками
```

```text
/ssh dev-server проверь статус Docker Compose и последние 100 строк логов сервиса api
```

```text
/review проверь текущие изменения, выполни релевантные тесты и дай pass/fail отчёт
```

```text
/security проведи read-only AppSec review авторизации и обработки пользовательского ввода
```

## Skills по ролям

Skills — это короткие рабочие инструкции, а не новые права. Каждый агент видит только свой набор:

| Агент | Skills |
|---|---|
| `team-lead` | делегирование и сводный отчёт |
| `software-engineer` | безопасная реализация, quality engineering, диагностика ошибок, React/Next.js performance и `find-docs` |
| `qa-engineer` (Quality Engineer) | Playwright E2E, Chrome DevTools диагностика, риск-ориентированное тестирование, accessibility и web-design review |
| `systems-engineer` | безопасные Windows- и SSH-операции |
| `devops-engineer` | контроль внешних GitHub-изменений и `find-docs` |
| `solution-architect` | сравнение вариантов, архитектурное решение и `find-docs` |
| `platform-engineer` | диагностический и подтверждаемый Docker/Compose workflow |
| `security-engineer` | AppSec, agent/MCP security audit, SCA и prompt-injection testing только в явно разрешённой области |

Skills обнаруживаются OpenCode автоматически после перезапуска. Они не обходят ограничения MCP и не отменяют подтверждения для внешних или рискованных действий.

## Serena и Context7

- `Serena` подключена только к `software-engineer`. Она даёт символьный обзор проекта, поиск определений и ссылок и точечные правки без чтения огромных файлов целиком. Контекст `codex` исключает дублирующий shell и грубые файловые операции.
- `Context7` доступна инженерным ролям, которым нужна документация. Сначала агент определяет точный ID библиотеки, затем получает актуальные справочники и примеры API. В запросы Context7 нельзя передавать секреты или приватный код.
- Semgrep установлен изолированно как локальный scanner, но не зарегистрирован как MCP: бесплатный MCP-интерфейс текущей версии устарел, а новый требует Semgrep Pro Engine. `security-engineer` может запустить scanner через подтверждаемый shell в рамках явно разрешённого проекта.

## GitHub: первый запуск

При первом обращении к агенту `devops-engineer` официальный GitHub MCP откроет OAuth-вход в браузере. Войдите в нужный GitHub-аккаунт и подтвердите доступ. Сервер настроен без `--read-only`, поэтому он умеет создавать и изменять Issues, PR, ветки, релизы и другие объекты GitHub. Агент всё равно запрашивает подтверждение перед внешними изменениями.

## Границы и безопасность

- Playwright и DevTools используют отдельные browser profiles и не получают ваши текущие cookies или пароли.
- Windows UI MCP не может управлять UAC и чужими окнами, запущенными от администратора.
- SSH использует ключи или aliases из `~/.ssh/config`; пароли и ключи не записываются в OpenCode.
- Docker MCP запускается из зафиксированного образа и не предлагает remove/prune/kill. Запуск, остановка, restart, build и Compose-действия агент отдельно согласует.
- Docker Research запускается в контейнере с проверкой подписи. Он предназначен для анализа и планирования, а не для бесконтрольного изменения контейнеров.
- MCP-инструменты доступны только профильным инженерам, поэтому `software-engineer` не перегружен посторонними схемами.
