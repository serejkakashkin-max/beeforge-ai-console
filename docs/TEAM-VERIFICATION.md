# Проверка команды BeeForge

Канонические инструкции агентов находятся в `opencode/opencode.template.json`.
Установщик читает этот шаблон; `tools/apply-serena-semantic-policy.ps1` переносит
те же prompts в существующую конфигурацию, сохраняя модели и прочие настройки.
После обновления плагина перезапустите OpenCode для загрузки новой версии.

## Поведение делегаций

Обычный маршрут: разработчик → при необходимости QA. Подтверждённый
`QA_FAILED` со списком дефектов разрешает один цикл разработчик → QA.
Повторная ошибка после этого возвращается пользователю. Один
`CONTEXT_ROLLOVER_REQUIRED` разрешает продолжение при нехватке контекста.
Внешний блокер требует нового ввода пользователя, а не немедленного повтора.

Guard восстанавливает состояние из истории OpenCode перед делегацией.
Повторное событие одного сообщения не сбрасывает бюджет; неизвестный статус
не считается успехом. Событие idle само по себе не подтверждает завершение.
Последний handoff автоматически добавляется к следующему заданию как данные.
Для QA и исправления его дефектов также сохраняется последний handoff разработчика;
общий текст этих пакетов ограничен 6000 символами, обрезка явно помечается.
Legacy-текст поддерживается; длинный пакет явно помечается truncated.
Редактирование типичных секретов — дополнительная мера, не гарантия отсутствия
в handoff произвольной чувствительной информации. Агенты не должны её включать.

## Проверки без запуска модели

```powershell
node .\tools\team-guard\v1.0.0\self-test.mjs
pwsh -File .\scripts\Test-BeePolicySync.ps1
pwsh -File .\scripts\Test-BeeSerenaMemory.ps1
node .\tools\team-guard\v1.0.0\evaluate-routing.mjs --check
```

Тесты воспроизводят QA repair, повторный дефект, перезапуск плагина, отмену,
завершение асинхронной задачи, дубли событий, отсутствие состояния и передачу
данных. Это проверки оркестрации, а не доказательство качества ответов LLM.

## Проверка выбора специалиста реальной моделью

Когда модель запущена и свободна, укажите действующий endpoint и alias:

```powershell
node .\tools\team-guard\v1.0.0\evaluate-routing.mjs --base-url http://127.0.0.1:8080/v1 --model Q2
```

Используются шесть фиксированных сценариев из `benchmarks/team-routing-cases.json`.
Инструменты только описываются модели: команды специалистов не выполняются.
Результат содержит выбранную роль, время и usage. Сравнивайте одинаковые
сценарии, модель и настройки. Тест оценивает только первую делегацию; качество
реализации и итоговую приёмку нужно проверять на отдельных тестовых проектах.
Модель автоматически не запускается; без явных параметров inference не начинается.

## Обновление skills

`scripts/Sync-BeeSkills.ps1` обновляет файлы установленных skills и сохраняет
предыдущие версии в `backups/skills`. Ошибочные вложенные копии `skill/skill`
перемещаются туда же, вне каталога обнаружения skills. Пользовательские дополнительные
файлы сохраняются. Тест установщика использует отдельный SkillRoot во временном
каталоге и не обновляет skills текущего пользователя.

## Актуальность Serena memory

Старая memory без отпечатков остаётся пригодной для чтения, но требует проверки.
При содержательном обновлении добавляется `Evidence SHA256: путь | sha256`
для небольших релевантных файлов. Изменение/удаление файла переводит memory
в NEEDS_REVIEW. Совпадение отпечатков подтверждает неизменность доказательств,
а не истинность всех выводов. Не нужно переписывать всю память ради VERIFIED.
