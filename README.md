# BeeForge AI Console

Локальная Windows-консоль для запуска GGUF-моделей через llama-server/BeeLlama,
синхронизации команды OpenCode и защищённого управления через личного Telegram-бота.

## Развёртывание на новом ПК

Репозиторий не содержит моделей, токенов, журналов, резервных копий и локального
runtime. Они создаются или выбираются на целевом компьютере.

Требования: Windows 10/11, PowerShell 7, Git, Node.js LTS, Python 3.11–3.13,
`uv`, OpenCode Desktop, совместимый `llama-server.exe` и GGUF-модель.

```powershell
git clone https://github.com/serejkakashkin-max/beeforge-ai-console.git "C:\AI\BeeForge AI Console"
Set-Location "C:\AI\BeeForge AI Console"
pwsh -File .\scripts\Install-BeeForge.ps1 -ConfigureOpenCode
```

Установщик:

- создаёт локальные конфигурации из безопасных шаблонов;
- сохраняет настроенные параметры профилей, но заменяет персональные пути;
- устанавливает Node.js MCP, Serena и локальное распознавание речи;
- скачивает Windows MCP и GitHub MCP с проверкой SHA256;
- устанавливает Team Lead, специалистов, skills и Telegram-плагин OpenCode;
- перед заменой существующего `opencode.json` сохраняет резервную копию.

Альтернативные пути можно передать параметрами:

```powershell
pwsh -File .\scripts\Install-BeeForge.ps1 `
  -ConfigureOpenCode `
  -ProjectRoot "D:\AI\Projects" `
  -ModelRoot "D:\Models" `
  -LlamaServerPath "D:\llama\llama-server.exe"
```

Telegram-токен в GitHub не хранится. После первого запуска откройте вкладку
Telegram, укажите собственные User ID/Chat ID и сохраните токен — он будет
зашифрован Windows DPAPI именно для нового пользователя.

Запуск интерфейса: `BEEFORGE-AI.cmd` или ярлык **BeeForge AI Console** на рабочем столе.

Все профили равноправны: любой из них можно изменять и удалять. Параметры следует
подбирать и проверять отдельно для каждой модели. Чтобы интерфейс всегда оставался
работоспособным, перед удалением единственного профиля нужно создать или
импортировать другой.

## Кнопки запуска

- **Сохранить профиль** — проверяет и записывает параметры, а при включённой
  галочке «Обновлять OpenCode» автоматически синхронизирует его конфигурацию.
- **Применить и перезапустить** — сохраняет форму, останавливает только управляемый
  PID, запускает профиль и после успешного `/health` синхронизирует OpenCode.
- **Запустить** — запускает сохранённую версию выбранного профиля.
- **Остановить** — останавливает только проверенный `llama-server.exe` из PID-файла.
- **Открыть live log** — открывает независимое окно PowerShell с prompt/decode tok/s.

Закрытие UI не останавливает сервер. При повторном открытии UI состояние читается
из `logs/qwen38-server.pid` и `logs/current-run.json`.

## Файлы

- `config/profiles.json` — профили и активный/последний рабочий профиль.
- `logs/current.stdout.log` — stdout текущего запуска.
- `logs/current.stderr.log` — stderr и метрики текущего запуска.
- `logs/qwen38-server.pid` — PID управляемого сервера.

При каждом новом запуске старые runtime-логи удаляются. Перед изменением OpenCode
создаётся резервная копия в `backups`; автоматически хранятся не более 10 таких
копий и не дольше 30 дней. В `benchmarks` постоянными считаются `results.csv` и
`README.md`; временные benchmark-артефакты хранятся не более 30 дней и 20 файлов.

## Быстрый туториал

1. Выберите профиль слева. Для экспериментов удобно использовать **Клон**, чтобы
   сохранить исходный набор параметров выбранной модели.
2. На вкладке **Основные** выберите GGUF, runtime, любое положительное значение
   context и параметры запуска.
3. Откройте вкладку **Ресурсы**. Сохранять профиль перед расчётом не нужно:
   прогноз берётся непосредственно из текущих полей формы и автоматически
   обновляется после их изменения. Проверьте ожидаемую
   dedicated VRAM, запас и перенос весов в RAM. Для постоянной работы желательно
   оставлять хотя бы 500–800 MiB VRAM.
   Параметр **GPU layers** выбирается из списка: `all`, затем от `64` до `0`.
   Уменьшение значения переносит часть весов модели из VRAM в системную RAM.
4. На вкладке **Производительность** настройте KV, reasoning, sampling и MTP.
   Оптимальный набор параметров зависит от конкретной модели и проверяется тестом.
5. **Сохранить профиль** записывает настройки без перезапуска и при включённой
   галочке автоматически синхронизирует OpenCode. Для нового vision-профиля
   image-capability добавляется после успешного запуска с projector.
   **Применить и перезапустить** сохраняет профиль, запускает сервер и ждёт `/health`.
6. Для наблюдения нажмите **Открыть live log**. Закрытие менеджера или live-log
   не останавливает модель.
7. Для завершения сервера нажмите **Остановить**. Если эксперимент не загрузился,
   изучите `logs/current.stderr.log`, исправьте профиль либо запустите другой.

## Встроенный benchmark

На вкладке **Тест** задаются примерный размер synthetic input, максимальное число
output tokens и конечный timeout. По умолчанию менеджер сначала сохраняет профиль,
перезапускает сервер и ждёт `/health`, поэтому измеряются именно введённые
параметры. Если перезапуск не нужен, снимите флажок применения профиля.
Если выбранный input вместе с output не помещается в context, менеджер заранее
показывает безопасный максимум и автоматически уменьшает input. Перед основным
запросом фактическое число токенов уточняется через BeeLlama
`/v1/chat/completions/input_tokens`.

Во время выполнения отображаются:

- фактические input/output tokens;
- prompt processing / prefill tok/s;
- decode / generation tok/s;
- elapsed time и причина завершения.

Кнопка **Стоп тест** завершает только benchmark-клиент. Сервер BeeLlama и OpenCode
остаются запущенными. Каждый запрос имеет `max_tokens` и timeout, поэтому
бесконтрольная генерация невозможна.

Оценка ресурсов является прогнозом, а не гарантией: точное потребление зависит
от архитектуры GGUF и версии runtime. Цветовая индикация показывает комфортный
запас, работу около предела либо риск Shared GPU Memory spill/OOM. Фактические
VRAM и RAM запущенного сервера отображаются рядом с прогнозом.

## AI-команда OpenCode

Вкладка **AI-команда** является редактором фактической конфигурации
`%USERPROFILE%\.config\opencode\opencode.json`. Она показывает Team Lead и всех
специалистов, их режим, модель, описание, системную инструкцию, skills, MCP,
разрешения и маршруты делегирования.

- **Новый** создаёт безопасного специалиста; **Клон** копирует выбранную роль для
  дальнейшей настройки.
- Флажок skill назначает агенту только существующий корректный `SKILL.md`.
- В таблице MCP столбец **Агенту** выдаёт доступ выбранному специалисту, а
  **Включён** управляет глобальным состоянием сервера в OpenCode.
- **Проверить MCP** выполняет конечный `initialize` с тайм-аутом 10 секунд. Для
  Docker выполняется только пассивная проверка Docker Engine; контейнеры не
  запускаются.
- **Сохранить изменения** валидирует модель, режим, skills, MCP и наличие хотя бы
  одного активного primary-агента, затем атомарно обновляет OpenCode.
- Перед каждым изменением создаётся резервная копия; кнопка восстановления
  возвращает последнюю конфигурацию редактора. Общий лимит — 10 резервных копий.
- Переключатель **Полный доступ** добавляет последним правилом `* = allow` в
  глобальные и агентские разрешения OpenCode. Перед включением показывается
  предупреждение. При выключении восстанавливаются только прежние деревья
  разрешений; остальные изменения `opencode.json`, сделанные в это время, сохраняются.
  Состояние видно в интерфейсе и записывается в локальный журнал.

Секреты MCP не отображаются: интерфейс показывает только имена переменных
окружения. Изменение executable и аргументов MCP намеренно оставлено в режиме
просмотра — это снижает риск случайного запуска произвольной команды из UI.

### Интернет-исследования команды

`Solution Architect`, `DevOps Engineer` и `Application Security Engineer`
получают официальный встроенный `websearch` OpenCode и чтение страниц через
`webfetch`. Для локального BeeLlama используется пользовательская переменная
`OPENCODE_ENABLE_EXA=1`; отдельный API-ключ не нужен. `Solution Architect` и
`DevOps Engineer` также имеют GitHub MCP, а skill `opencode-web-research`
требует проверять источники и явно отделять подтверждённые факты от выводов.
Team Lead не выполняет поиск самостоятельно, а делегирует его профильному агенту.

### Планирование и утверждение

Запросы «составь план», «сначала план», «пока не приступай» и команда `/plan`
работают строго read-only. Team Lead может собрать сведения, но не запускает
исполнителей и не изменяет проект. После выдачи плана он ожидает отдельное новое
сообщение, например: **«План утверждаю, приступай»**. Только после него начинается
реализация. Фраза «потом приступим» не считается утверждением текущего плана.

## Telegram Bridge

Вкладка **Telegram** подключает одного личного Telegram-бота к уже запущенному
OpenCode. Второй экземпляр OpenCode и публичный входящий порт не создаются:
плагин OpenCode связывается с мостом только через `127.0.0.1`, а Telegram работает
через long polling.

1. Создайте бота через BotFather и вставьте токен в защищённое поле. После
   сохранения токен шифруется Windows DPAPI для текущего пользователя и больше не
   показывается в интерфейсе.
2. Укажите собственные Telegram User ID и ID личного чата. Группы и другие
   пользователи игнорируются.
3. Добавьте только те папки проектов, которыми разрешено управлять удалённо.
4. Нажмите **Проверить бота**, затем включите интеграцию и **Запустить мост**.
   При следующем запуске OpenCode глобальный плагин зарегистрирует разрешённый
   проект. Все новые задачи из Telegram создаются только через Team Lead.

Основные команды: `/status`, `/model`, `/profiles`, `/launch`, `/fullaccess`, `/closeall`,
`/projects`, `/sessions`, `/new <задача>`,
`/messages`, `/files [путь]`, `/worktrees`, `/worktree create <имя>`, `/task`, `/tasklist`,
`/taskdel`, `/queue`, `/queueclear`, `/create <имя>`, `/createat <полный путь>`,
`/stop`, `/mute`, `/unmute` и `/help`.
`/launch` безопасно запускает последний успешный профиль
BeeLlama с сохранёнными параметрами, ждёт состояния READY и только затем открывает
выбранный проект OpenCode. Если модель уже готова, второй экземпляр не создаётся.
В быстром меню показано одно действие завершения: `/closeall` выгружает модель и
закрывает OpenCode и BeeForge AI Console. Действие требует подтверждения в Telegram. Процессы
выбираются по точным путям, а Telegram Bridge остаётся запущенным, поэтому приложения
можно снова открыть из бота. `/stop` по-прежнему останавливает только выбранную задачу
OpenCode и не закрывает приложения.

`/fullaccess` показывает текущее состояние и позволяет включить или выключить
полный доступ. Включение через Telegram требует двух последовательных подтверждений
и доступно только настроенным User ID и личному Chat ID. Выключение сразу возвращает
предыдущие правила. Полный доступ снимает системные запросы разрешений на файлы,
shell, интернет и MCP, поэтому его следует включать только для доверенной задачи.

### Вложения Telegram

Фото, документы, архивы, текстовые файлы, HTML, аудио и видео из личного чата бота сохраняются в `.beeforge/telegram/inbox/<дата>/` выбранного проекта и передаются Team Lead как файловая часть OpenCode. Подпись к файлу используется как текст задачи; после `/new` вложение может быть первым сообщением новой основной сессии. Облачный Telegram Bot API ограничивает входящее скачивание 20 МБ.

Несколько файлов или фотографий, отправленных одним Telegram-альбомом, объединяются в
один запрос Team Lead. Голосовые сообщения дополнительно распознаются локальным
`faster-whisper` в отдельном CPU-процессе: аудио не отправляется стороннему STT-сервису
и не занимает VRAM BeeLlama. Модель загружается при первом голосовом сообщении и
освобождается после простоя.

Для обратной отправки Team Lead отмечает явно запрошенный пользователем результат строкой `TELEGRAM_FILE: относительный/путь`. Все файлы, включая PNG, JPEG и WebP, отправляются Telegram-документами: это сохраняет исходные байты и не даёт Telegram пережимать картинки. Разрешены только обычные файлы внутри выбранного проекта размером до 50 МБ; `.env`, ключи, credentials, `.git` и каталоги secrets автоматически блокируются. Существующий файл также можно получить командой `/send относительный\\путь`.
Обычное сообщение продолжает выбранную сессию. Запрос разрешения можно одобрить
однократно, сохранить как постоянное правило OpenCode или отклонить; критические
операции требуют второго подтверждения.

Одно закреплённое сообщение показывает актуальное состояние без периодического
спама. Если основная сессия занята, новые обычные сообщения и вложения сохраняются в
очередь и передаются Team Lead после перехода сессии в `idle`. `/messages` показывает
только безопасный текст основной сессии и позволяет создать fork. Откат сообщения и
удаление worktree требуют отдельного повторного подтверждения.

Планировщик принимает только задачи Team Lead в выбранном разрешённом проекте:
`/task 09:30 текст` запускает задачу ежедневно, `/task 2026-09-01 09:30 текст` — один
раз, `/task every monday 09:30 текст` — еженедельно. Если проект не открыт или занят,
задача не запускается параллельно, а откладывается до безопасного момента.

Завершение дочерней сессии отображается как компактный отчёт соответствующего
специалиста. После возврата управления итог основной сессии всегда отправляется как
**финальный отчёт Team Lead**. Текст передаётся полностью; если он не помещается в
одно сообщение Telegram, мост разбивает его на последовательно пронумерованные части.
Завершённый ответ не дублируется отдельной карточкой «Обновление работы».

Мост не передаёт reasoning, полные tool outputs, исходники, `.env` и полный diff.
Локальный журнал решений находится в `logs/telegram-bridge.log`. Остановка моста
не останавливает BeeLlama или OpenCode, а закрытие UI не завершает уже запущенный
мост. После изменения настроек запущенный мост перезапускается безопасно; после
включения глобального плагина OpenCode требуется перезапустить один раз.
